# GCA 0.3.0

[简体中文](https://github.com/PANZERLEADER/git-contribution-analyzer/blob/v0.3.0/doc/zh-CN/release-0.3.0.md)

## Highlights

- Split one work assessment into persisted calendar week, month, or quarter runs and a replayable
  series report. Series use one shared workload baseline and include period-over-period changes plus
  year-over-year changes when the corresponding prior-year period is present.
- Attribute work by authored, committed, merged, landed, or released Git time. Landed and merged
  times use target-branch first-parent integration points; released time uses tag creation time.
- Compare two historical `WORK_ASSESSMENT` runs with overall, size, difficulty, and per-person
  deltas. Comparability warnings identify rule-version, time-basis, and cohort differences.
- Interpret offset-free `--since` and `--until` values in the host system time zone while preserving
  explicit `Z` and numeric offsets. Calendar boundaries follow the same local time zone, including
  system offset changes.
- Reject reversed time ranges and normalize Git index timestamps and SQLite query bindings to UTC.

## Compatibility And Upgrade

- Existing analysis, `work-assessment/v1`, `work-assessment/v2`, resume, and series run payloads
  remain immutable and replayable. Series reports created before `inputTimeZone` was recorded render
  as `LEGACY_UTC`.
- No database migration is required. Run `gca index <repo>` once after upgrading so timestamps in an
  existing Git index are rebuilt with UTC normalization, then run `gca doctor <repo> --json`.
- Existing commands remain compatible. Periodic assessment requires both `--since` and `--until`;
  explicit offsets remain authoritative.

## Interpretation Boundary

- Trends and historical deltas compare Git evidence under the same repository, cohort, filters, and
  rule versions. They do not measure hours worked, employee value, compensation, or promotion
  readiness.
- Partial boundary periods are marked and should not be directly compared with complete periods.
- LLM Providers do not create or modify deterministic time attribution, workload, difficulty, or
  comparison values.

## Release Gates

The release commit must pass the Windows, Linux, and macOS CI matrix, credential-history scan,
isolated wheel lifecycle, pipx installation, standalone artifact smoke tests, and all version/Schema
compatibility tests. The tagged workflow publishes SHA-256 checksums and uses this file together
with the Chinese release notes for `v0.3.0`.
