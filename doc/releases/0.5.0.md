# GCA 0.5.0

[简体中文](../zh-CN/release-0.5.0.md)

## Highlights

- Add observation-only historical structural baselines from local indexed Git history, including
  repository-relative hotspots, repeated co-change relationships, conditional ratios, Jaccard and
  explicit hub filtering.
- Add `gca structural status/rebuild/show/prune` and the matching desktop Structure view.
- Ship the conservative `community-baseline-v1` profile. Automatic difficulty promotion remains
  fixed to `false`; structural results do not affect workload, difficulty, delivery, ranking,
  resume claims or LLM context.
- Persist sanitized BUILDING, FAILED, CANCELLED and STALE diagnostics while publishing completed
  baselines atomically.

## Compatibility And Upgrade

- Repository `status --json` now emits `status/v2` with a structural cache summary. The original
  `schemas/status/v1.json` contract remains unchanged.
- Existing work-assessment v1/v2, ranking, resume and historical run payloads remain unchanged.
- Run `gca index <repo>` after upgrading to populate structural commit facts, then use
  `gca structural rebuild <repo> --cutoff <exclusive-boundary>` when a historical baseline is
  needed.
- Migration `0007_structural_baselines` contains rebuildable derived data and supports downgrade
  without modifying Git history or persisted analysis runs.

## Validation

- Local Windows validation covers full/incremental equivalence, warm cache reuse, force-push stale
  handling, failed/cancelled diagnostics, migration downgrade/upgrade and Schema compatibility.
- Cross-platform wheel and GUI validation remains enforced by the existing Windows/Linux/macOS CI
  matrices before release publication.
