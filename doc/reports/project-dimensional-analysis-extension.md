# Project-Wide Deterministic Analysis Extension

## Scope

This extension adds a project report mode:

```powershell
gca analyze <repository> --all --no-llm --json
```

The mode analyzes every indexed Git Person with matching commits, including unconfirmed
identities. It does not auto-merge aliases beyond the existing deterministic identity rules and
manual mappings. Each unconfirmed identity remains visible and produces an identity warning.

## Report Dimensions

Every person report and the aggregate project report expose two independent summaries:

- Technical: dominant modules, commit/change profile, and evidence-backed capability signals.
- Business: work-area domains inferred from conventional commit scopes, issue keys, or module
  fallback clusters.

Business domains describe where changes were made. Git history alone cannot prove revenue,
conversion, customer outcome, business ownership, or sole authorship, so those claims are never
generated by deterministic analysis.

## Contracts

- `--person` and `--all` are mutually exclusive.
- Project mode currently requires `--no-llm`.
- Project evidence references use `<person-id>:<evidence-id>` to avoid collisions between the
  per-person `EV-001` sequences.
- Project runs persist the versioned aggregate JSON but do not flatten per-person Contribution
  Items and Evidence into shared detail tables, whose local IDs are only unique per person.
- `schemas/project-report/v1.json` validates the persisted project report.
- `schemas/analysis/v1.json` accepts either a Person or Project analysis envelope.

## Usage Notes

Project Markdown intentionally summarizes contributors, shows the 30 most active business
domains, and limits inline Evidence references instead of expanding every commit or Evidence
record. The JSON report retains every project business domain and the complete per-person
deterministic subreports for auditing and downstream processing.
